PostgreSQL 16

Parser support

Parser support usually matches PostgreSQL 16, but the checker may still fall back to the nearest compatible grammar when syntax support lags or parsing fails.

ADD COLUMN default

PostgreSQL 16 keeps the modern fast-default path for many non-volatile defaults, but the checker still cannot prove exact volatility or deployment safety from SQL alone.

Concurrent indexes

Concurrent create, drop, and reindex paths remain available and are usually preferred for online rollouts, subject to the usual non-transactional rules.

Enum changes

Enum additions remain transaction-safe in PostgreSQL 16, but application rollout order still matters because new labels are not visible until commit.

Generated columns

Stored generated columns are supported. The checker treats them as potentially rewrite-heavy because PostgreSQL may need to materialize values for existing rows.

Raw SQL

Transaction assumption

Assume no transaction

Raw SQL does not assume a transaction wrapper by default.

Safer rollout defaults

Indexes: Use dedicated non-transactional steps for CREATE INDEX CONCURRENTLY and DROP INDEX CONCURRENTLY.

Constraints: Prefer NOT VALID plus VALIDATE CONSTRAINT and split large backfills from schema DDL.

Transaction disable hint: Keep online-only DDL outside any explicit BEGIN ... COMMIT block.

Common risks

Explicit BEGIN ... COMMIT blocks are easy to miss during review.

Operational guardrails like lock_timeout are only present if teams add them deliberately.

Review checklist

Confirm whether the script contains an explicit transaction block.

Add lock_timeout and statement_timeout before risky DDL.

Split backfills and destructive cleanup from additive schema changes.
